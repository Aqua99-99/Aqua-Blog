# 노션 연동 포트폴리오·블로그 설계

작성일: 2026-11-12

## 목적

황준현(영남이공대학교 사이버보안과 2학년)의 공부 기록과 포트폴리오를 한 사이트에 담는다. 독자는 셋이다.

- 면접관: 1~2분 안에 자격증, 활동, 프로젝트를 훑어볼 수 있어야 한다.
- 본인: 노션에 쓰던 그대로 쓰고, 나중에 다시 찾기 쉬워야 한다.
- 같은 분야를 공부하는 사람: 검색으로 글에 들어올 수 있어야 한다.

기존 Hugo + AWS(S3, CloudFront) 블로그는 템플릿 문법이 낯설고, AWS 비용 관리가 부담이고, 글 쓰는 흐름에 손이 가지 않아 교체한다.

## 성공 기준

1. 노션 데이터베이스에서 "공개"를 체크하면, 코드를 건드리지 않고 하루 안에 사이트에 반영된다.
2. 호스팅 비용이 0원이다.
3. 1차 범위(자격증·수료 7개 페이지, 대외활동 5건)가 포트폴리오 화면에 올라간다.
4. 기존 글 3편이 새 사이트에서 그대로 읽힌다.
5. 공개 체크를 하지 않은 노션 내용은 사이트와 저장소 어디에도 들어가지 않는다.

## 범위

### 1차 (이 문서)

- 사이트를 Astro로 다시 만들고 GitHub Pages에 올린다.
- 노션 "포트폴리오" 데이터베이스를 만들고 자격증·수료·대외활동을 옮긴다.
- 홈, 포트폴리오, 활동 상세, 글 목록, 글 상세, 소개 화면을 만든다.
- 기존 글 3편을 저장소 안 마크다운으로 옮긴다.
- AWS 자원을 정리한다.

### 나중에 (별도 설계)

- 2차: 노션 "블로그" 데이터베이스와 공부 정리·실습 글(SCS-C03, PortSwigger, bandit 등), 검색 기능.
- 3차: 수업 필기. 강의 자료를 옮긴 부분은 제외하고 과목별로 검수한다.
- 내 도메인 연결, 댓글.

### 올리지 않는 것

- `exam-bank`, 학교 시험 문제, 자격증 실제 기출 복원.
- 개인 페이지(가계부, 생일, 저장).

## 구조

```
노션 "포트폴리오" DB ──(노션 API, 공개 항목만)──┐
                                               ├─> GitHub Actions: Astro 빌드 ─> GitHub Pages
저장소의 마크다운 글 ──────────────────────────┘
```

구성 요소는 넷이고, 각각 따로 바꿀 수 있다.

### 1. 노션 데이터베이스 "포트폴리오"

기존 `영남이공대학교` 페이지와 하위 페이지는 건드리지 않는다. 새 데이터베이스에 내용을 복사해 넣는다.

| 속성 | 종류 | 설명 |
|---|---|---|
| 이름 | 제목 | 자격증이나 활동의 이름 |
| 구분 | 선택 | 자격증 / 수료 / 수상 / 대외활동 |
| 기관 | 텍스트 | 발급·주관 기관 |
| 날짜 | 날짜 | 취득일 또는 활동 기간(범위 가능) |
| 요약 | 텍스트 | 목록에 보이는 한두 문장 |
| 증빙 | 파일 | 개인정보를 가린 수료증 이미지나 PDF |
| 대표 | 체크박스 | 홈 화면에 올릴 항목 |
| 공개 | 체크박스 | 체크한 항목만 사이트에 나온다 |

페이지 본문이 있으면 그 항목은 상세 화면을 갖는다. 본문이 비어 있으면 목록에만 나온다.

### 2. 노션 읽기 모듈

빌드할 때 한 번 실행된다.

- 입력: 노션 연동 토큰, 데이터베이스 ID(둘 다 환경 변수).
- 동작: "공개"가 체크된 항목만 조회하고, 본문 블록을 HTML로 바꾸고, 이미지와 증빙 파일을 빌드 결과물 안으로 내려받는다. 노션 파일 주소는 만료되므로 원본 주소를 페이지에 남기지 않는다.
- 출력: 화면이 쓰는 항목 배열(이름, 구분, 기관, 날짜, 요약, 증빙 경로, 대표 여부, 본문 HTML, 주소용 슬러그).
- 지원 블록: 문단, 제목 1~3, 목록, 인용, 코드, 이미지, 파일, 구분선, 굵게·기울임·링크. 그 밖의 블록은 건너뛰고 빌드 로그에 경고를 남긴다.

화면은 이 모듈의 출력만 쓰고 노션 API를 직접 부르지 않는다. 2차에서 "블로그" 데이터베이스를 붙일 때 같은 모듈을 다시 쓴다.

### 3. 사이트 (Astro)

| 주소 | 화면 | 내용 |
|---|---|---|
| `/` | 홈 | 이름과 소개, 대표 자격증 띠, 대표 활동 카드, 최근 글 3편 |
| `/portfolio/` | 포트폴리오 | 자격증·수료 표, 대외활동 타임라인(최신순), 프로젝트 카드 |
| `/portfolio/<슬러그>/` | 활동 상세 | 노션 본문과 사진 |
| `/posts/` | 글 목록 | 날짜순 목록, 태그 |
| `/posts/<슬러그>/` | 글 상세 | 마크다운 본문, 코드 하이라이팅 |
| `/tags/<태그>/` | 태그별 글 | 해당 태그의 글 목록 |
| `/about/` | 소개 | 학력, 다루는 기술, 연락처 |

- 프로젝트 카드와 소개 정보는 저장소 안의 데이터 파일 하나로 관리한다. 자주 바뀌지 않아서 노션에 두지 않는다.
- 디자인은 확정한 시안을 따른다: 회백색 바탕(#F6F7F9), 강조색 파랑(#0B5FA5) 하나, 본문 IBM Plex Sans KR, 날짜·구분 표시는 IBM Plex Mono. 휴대폰 너비에서 메뉴와 카드가 세로로 쌓이고 표는 가로로 스크롤된다.
- 검색 노출을 위해 페이지마다 제목·설명 메타 태그, 사이트맵, RSS를 만든다.

### 4. 배포 (GitHub Actions → GitHub Pages)

- 실행 시점: `main`에 push, 하루 한 번 예약 실행, 수동 실행 버튼.
- 순서: 코드 받기 → 의존성 설치 → 노션 읽기를 포함한 빌드 → Pages에 올리기.
- 비밀값: 노션 토큰과 데이터베이스 ID는 저장소 Secrets에 둔다.
- 주소: `https://aqua99-99.github.io/Aqua-Blog/`. 모든 내부 링크는 이 하위 경로를 기준으로 만든다.

## 오류 처리

- 노션 API가 실패하거나 토큰이 없으면 빌드를 실패시킨다. 빈 포트폴리오로 덮어쓰지 않고, 직전에 올라간 사이트가 그대로 남는다.
- 로컬 개발에서 토큰이 없으면 저장소에 있는 예시 데이터로 화면을 띄운다. 이 대체는 로컬 개발 명령에서만 동작한다.
- 이미지 하나를 내려받지 못하면 빌드를 실패시킨다. 깨진 이미지가 공개되는 것보다 낫다.
- 필수 속성(이름, 구분)이 빈 공개 항목은 빌드 로그에 이름을 적고 빌드를 실패시킨다.

## 개인정보

- 실명과 학교는 공개한다(본인 확인).
- 증빙 파일은 올리기 전에 하나씩 열어 생년월일, 수험번호, 주소가 있으면 가린다. 가린 파일만 "증빙" 속성에 넣는다.
- 공개 이메일은 본인이 정한 주소만 쓴다. 정하지 않으면 GitHub 링크만 둔다.

## 옮기기와 정리 순서

1. 새 사이트를 `redesign/astro-notion` 브랜치에서 만든다. 기존 Hugo 파일은 이 브랜치에서 지운다.
2. 기존 글 3편을 마크다운 그대로 옮기고 머리말 형식만 맞춘다.
3. 노션 데이터베이스를 만들고 1차 범위 항목을 채운다.
4. 본인이 노션 연동 토큰을 발급하고 저장소 Secrets에 넣는다. Pages 설정도 본인이 켠다.
5. `main`에 합치고 새 주소에서 화면을 확인한다.
6. 확인이 끝나면 본인이 AWS에서 CloudFront 배포, S3 버킷, 배포용 IAM 역할을 삭제한다. 그 전까지 기존 블로그는 살아 있다.

## 시험

- 노션 읽기 모듈: 저장해 둔 API 응답 예시로 단위 시험을 한다. 공개 항목만 남는지, 블록이 HTML로 바뀌는지, 지원하지 않는 블록을 건너뛰는지, 필수 속성이 빠지면 실패하는지 확인한다.
- 사이트: 예시 데이터로 빌드가 성공하는지, 모든 화면 주소가 만들어지는지, 내부 링크가 하위 경로에서 깨지지 않는지 확인한다.
- 배포 전: 실제 노션 데이터로 빌드한 결과를 로컬에서 띄워 휴대폰 너비와 데스크톱 너비에서 본다.

## 확정하지 못한 값

만드는 동안 채운다. 설계에는 영향이 없다.

- 자격증 취득일 대부분, TOLIS·ISO/IEC 27001·CO-WEEK ACADEMY·RISE 캠프의 발급·주관 기관: 증빙 파일에서 확인한다.
- 동아리(YESS)와 CPS Festival 활동 기간: 본인에게 묻는다.
- 프로젝트 카드에 올릴 저장소와 한 줄 설명: 본인에게 묻는다.
- 공개 이메일: 본인에게 묻는다.
- RISE 캠프를 "수상"으로 분류하는 것이 맞는지: 본인에게 묻는다.
